## 0 为什么 1× 一定糊



* `ModLoader` 的 `Textures/Items` 分支：`PPU 100`、`Point`、`Clamp`、无 mipmap，`Sprite.Create` 用纹理原尺寸。

* 分辨率表：`960×540` / `1920×1080` / `3840×2160` 开 Pixel Perfect Camera（整数放大）；`1280×720` / `1366×768` / `1600×900` / `2560×1440` 关闭。

* 1080p 下 288×211 被放大约 2 倍，每个美术像素占 2×2 屏幕像素 → 屏幕像素天生不够。

* 订阅 MOD 的 “清楚”= 1000×1500 级原稿 + Bilinear + mipmap + 按图尺寸反算 PPU。

* **把 288 成品放大补不回来；4× 必须从高分辨率首图转换。**

## 1.5 标准流程（照抄即可；2026-11-19 定稿版）

> 这套是唯一的标准做法：参考图 → 生图 → 选首图 → 抠图 → 定体型 → 配色板 → 转换 → 验收与落位。下面每步都带实测数字，照做即可，不要自创变体。

**① 找参考图（2–3 张原作 + 3 张原版）**



* 原作图 2–3 张：优先官方设定 / 动画截图，正面或四分之三身、脸清楚、服装完整；不要选同人画风差异太大的图，必须能看清 3–5 个识别特征（发型发色、外套、内搭、标志配饰、气质）。

* 存成 `<MOD>/ref/<角色>_n*.png`，原图不裁不改；`upload_reference` 上传拿 URL。

* 原版锚点固定取 3 张同性别胸像：`tools/out/char_ref/<gender>Upper_<N>_full.png`（女性用 `femaleUpper_4/6/9`）。它们只是**画风 / 构图 / 色板参考**，不是要产出的 1× 成品。

**② 生图**

`image_gen`、`image model`、**1152×844**、5–6 张参考图（1–3 原版，4–6 原作；只选 2 张原作时没有图 6）。用下面的模板，只替换角色描述段：



```
参考图1、图2、图3是同一款太空酒馆游戏的角色胸像像素立绘，画风、构图、色板请严格沿用，它们的背景都是透明空区域。
参考图4、图5、图6只是《<作品>》<角色名>的人物特征参考（仅提取服装款式/配色与脸部发型特征，不复制原图背景，也不按参考图拉成全身）：图4是<服饰参考说明>；图5、图6是<脸部/发型特写说明>。
生成<角色名>的同人酒客形象：<年龄/气质>；<发型与挑染>；<皮肤、瞳色、眼型、睫毛>；穿<服装/领巾/徽章>；表情是<情绪与嘴角/眉眼表现>，眼神<视线方向>。
这一张是给 4 倍分辨率使用的高清像素画：保持像素画硬边与清晰分块，在 1–2 像素级细节处合理分层表现发丝分组、布料结构、眼睛虹膜层次与领口光影，避免模糊马赛克或涂抹渐变。
头肩关系自然：头部不放大，脖子长度正常偏短，头靠近肩膀，躯干紧凑；肩宽按<体型>，不要宽肩也不要做成纸片人；不要幼童脸、不要 Q 版、不要大头娃娃。动作不写叉腰、插兜、大幅挥手或下半身动作，防止镜头拉远。
胸像（Bust-up）立绘构图：从头顶到胸部下方一点精确裁切，露出完整肩线与锁骨，聚焦面部神态、肩颈线条与胸口衣领配饰，不出现腰部及以下身体部位；头部含头发占画面高度约 38–40%，头顶留约 8% 空白，左右各留 8–10% 余量，人物居中不贴边。
高光只用与底色同色系的 1–2 档相邻色，至少 8 像素成簇；不要跨色系亮斑、白色点或孤立高光。
严格像素画：硬边、清晰分块、无渐变、无柔光、无照片感。
背景：人物以外的区域全部是纯色深青（#1A2A33）的平涂背景，单一颜色，无渐变、纹理、场景、文字、光晕或外描边；画面里只有人物和纯色背景。
```



* **同一 prompt 连出 2–3 版（一次请求），然后挑一版**：这 2–3 版就是角色的 “首图批次”，构图 / 脸 / 服装最合适的那版直接去做 4×；**这是本角色唯一一次生图**，之后不得再调用 `image_gen` / `image_gen`，不补 4× 首图、不重开批次（第二次生成几乎一定换脸）。
* **生图前先查 `ref/<角色>_gen.log`**：不存在才允许调用一次；生成后写入 `batches=1`、日期、候选数、选中的文件。文件已存在就直接停，只从日志指向的那批里挑。

* **动作只写肩 / 胸高度**：**不写叉腰、插兜、大幅挥手、展示下半身**—— 模型会为了装下大动作把镜头拉到腰 / 全身。

* **4× 表情不限**：闭口微笑、平嘴、撇嘴、张嘴、大笑、露齿都可以写；**不要写唇线粗细、深几档、禁止半张嘴、禁止露齿、降采样自检**。情绪交给眉眼与唇角方向即可。

* 模型通常返 `1794×1314`，正常。

**③ 选首图（只能在批次内挑）**

从这次返回的 2–3 版里挑构图、脸、服装最合适的一版；它就是角色基准。**不许新开批次、不许换 prompt 再试**——画布头占比 36–45%（人物 bbox 46–58%）属店内常态，不因“看着头大/超宽”重生成。

**④ 抠图**



```
image CLI image remove-image-background --image-url "<MOD>\tools\out\patron\raw_<角色>4x.png" --scene general --output-format png
```

下载为 `raw_<角色>4x_matte.png`，量 bbox 与 aspect（`alpha>10`）。

> `--image-url` 这里传的是**本地绝对路径**（image CLI 直接读本地文件，不是网址）；只有参考图那一步才需要 `upload_reference` 换 URL 给 `image_gen`。

**⑤ 定体型（先看 aspect，再定 height）**



* 1× 目标高 ×4 = 4× 目标高（纤细 145–160 → 580–640）。

* **普通角色**：宽度 = height × aspect，必须落进体型表区间（纤细 400–480）；`--height = min(目标高, 宽上限 / aspect) − 1`。例（某角色）：aspect 0.788、目标 624 会得宽 492（超 480），改传 604 → 477×606，过线。`--height` 传的是描边前高度，最终看 JSON `figure`。

* **宽发女角色（长卷发 / 双马尾 / 披肩大波浪）走“肩线宽”口径**：`--height` 直接按目标档定（如普通 636），宽度只看**左右肩头 / 上臂外缘（含袖子、不含肩线外飘散发丝）**。肩线宽落表即通过；总 bbox 允许超表，但要同时满足：① 发丝不碰画布左右边缘（每侧 ≥8%，1152 宽下 ≥92px）；② `figure` 总宽 ≤ 1.15×人物高；③ 不 squeeze。量法：在 4× 图上量肩线宽，或在 6× 预览上量后除以 6 再乘 4 换回画布 px；也可以跑 `python scripts/measure_body_width.py <png>` 逐行看 central / span / 外侧发丝，取肩头 / 上臂外缘那行的 central 宽。把数值写进 `<角色>_gen.log` 的 `body_width=`。

* **只有肩线宽也超表时才收**：先在首批里换一版肩 / 袖最窄的；仍超就按「宽肩」档 560–620 收；总宽 >1.15×高 或发丝碰边则降 `--height` 或换批次里更窄的一版。**任何情况都不要 squeeze 硬压，也不要重生成**。

**⑥ 配 28–30 色板**

`references/palettes/<角色>_4x.json`，配额见第 4 节；实测示例 30 色（头发 6 / 肤 6 / 深蓝 4 / 红 5 / 白 2 / 眼 2 / 黄 2 / 唇・口腔 2（可选）/ 描边 1）。**唇色只是备用色，不代表要写唇部约束。**

**⑦ 转换（量化 + 硬 alpha + thin）**



```
python scripts/convert_character.py --src raw_<角色>4x_matte.png --out <key>4x_o1.png `
  --key <key> --palette references/palettes/<角色>_4x.json `
  --squeeze 1.0 --height 604 --canvas 1152x844 --resample LANCZOS --outline-mode thin --despeckle 7

python scripts/add_outline_rings.py <key>4x_o1.png <key>4x.png 1   # 2px 定稿
```

> 上面 `--height 604` 是**该示例的值，不要照抄**；换角色按 §1.5⑤ 用 `min(目标高, 宽上限 / aspect) − 1` 重算。

**⑧ 验收与落位（硬线）**

`alpha [0,255]`、`distinct_colors 28–30`、`edge_bad 0`、`body_width`（肩线宽）在体型表 ×4 宽度区间、`figure` 高度落表（宽发角色总宽另按“不碰边 + ≤1.15×高”判）、`center_x≈576`、`bottom_gap 0`、**下缘落在胸部下方一点（无腰、无腹、无手）**、6× 预览无色阶断层、1080p/4K 各看一眼。旧 1× 只用来对比世界尺寸，不作为验收项。

落位：`Textures/Items/<key>4x.png`（只交 4×，不再生成 1×）→ `build.cmd` → 校 `dist` 同 sha1 → 1080p 并排对照图 → 通知 coding agent（PPU 自动 400、Bilinear、mipmap 关）。

## 2 生成：直接出 4×（不要放大成品）

**这一节一生只用一次。** 生成前必须已按 §1.5 ① 备好参考图，prompt 必须写死“长发收拢在肩后、不越肩线、不碰左右边缘”，否则首批会全员超宽。

`image_gen` + `image model`，尺寸 **1152×844**，参考图 5–6 张：3 张原版 `maleUpper/femaleUpper`（构图 / 占比 / 色板锚点）+ 2–3 张原作设定（同人角色）。**完整 prompt 见§1.5②，直接照抄**；本节只说明它和 1× 模板的差异。

在 1.5 节②的模板上做三件事（**不要再套旧 1× 模板的任何唇部段**）：



* **保留**所有像素画句：`严格像素画：硬边、清晰分块、无渐变、无柔光、无照片感`（现行模板已去掉“颜色少”，不再和 28–30 色打架）。

* **追加** 4× 专属句（放在 “胸像（Bust-up）立绘构图” 那句之前）：



```
这一张是给 4 倍分辨率使用的高清像素画：保持像素画硬边风格，用尽量多的细小色阶去表现发丝分组、布料褶皱、眼睛虹膜层次和袖口光影，细节下沉到 1–2 像素级，不要输出低清马赛克块。
```



* **嘴部不写特化句**（2026-11-19 起）：4× 不再要求唇线粗细、比肤色深 2–3 档、禁止半张嘴、降采样自检 —— 那套只服务 1× 的 1/7 压缩链。表情按角色正常写（不服输的笑 / 平嘴 / 略蹙眉），把情绪交给整张脸（眉眼、唇角方向），不要用 “唇线 30px” 这类尺寸句。

* 配饰 / 布料线条同理：不再按像素数写粗细，只写 “高光同色系、连成簇”。

### 构图：宽高比是 4× 的第一杀手（2026-11-19 实测）

模型默认给 “大头特写”，头占画高 55–60%，aspect 0.86 → 按纤细体型高度换算会超过宽度上限。prompt 必须写死：



```
胸像立绘构图，中特写镜头，画面取景从头顶到胸部下方一点精确裁切，聚焦人物面部神态、肩颈线条与胸口衣领配饰细节，不出现腰部及以下身体部位。
构图（严格按此执行）：半身胸像，从头顶画到上胸/胸口上方，肩线与锁骨完整可见，不要裁掉肩膀；头部含头发的高度只占画面高度的 38–40%，头顶到画面上沿留 8% 空白，左右各留 8–10% 余量，人物别贴边；看起来像中景半身像，不是脸部特写。
```

实测同一角色同一参考：无约束 aspect 0.864；加 “40–45%、留 8%” 到 0.818；写 “38–40%、下方裁到胸口” 到 **0.765**（475×624，落在纤细 400–480 / 580–640）。**这句必须在唯一那次生图前就写进 prompt**；首批没压下来也不许重生成，只能按 §1.5⑤ 在批次内换版或按宽肩档收，不要靠 squeeze 硬压。

### 头身比：只用来选版，不用来返工（2026-11-20 强约束）

* 口径：头高（发顶→下巴）/ 画布 844。现有女性 4× 约 36–44%（DeepSeek 示例 43.2%）；换成人物 bbox 是 46–58%。
* 「38–40%」是生成时的构图指令，不是验收尺；拿它去卡 bbox，会把多个角色的店内常态判成不合格。
* 量 `python scripts/measure_head.py <png>`（露颈、刘海切断用 `--chin`）只用来看“批次里哪版最接近店内常态”，**不是重生成的理由**；即使「画布 >46% + aspect 超表 + 五官被裁」三条同时成立，也只能换批次内另一版或改裁切/宽肩档，**不得补版、不得重开批次**。
* 曾有角色因“看着头大”多出 3 版废稿，另一个角色因“肩宽超表”连开 3 批共 8 张，都是这条规则要防的事。

背景仍用纯深青 `#1A2A33` 平涂 → matting tool `general` 抠图（`--scene human` 对二次元全透明，别用）。

## 4 4× 色板：28–30 色，按原图实测配

**不要沿用 1× 的 18–24 色**：4× 下少 8 档必定色阶断层。标准配额：



* 头发 6–7 档（暗 → 中 → 亮，含最亮高光）

* 主衣 6–7 档（按服装主色，如深蓝水手服要有深 / 中 / 亮 / 高光四段）

* 皮肤 6–7 档（高光到深阴影）

* 眼睛 2–3 档（虹膜 + 瞳孔 + 眼白 / 亮部）

* 配饰 2–4 档（领巾红、徽章黄、手套红等）

* 唇 / 口腔色 0–2 档（**可选**，4× 不再强制）

* 最深描边 1 档：`41,34,52`

取色方法：按 bbox 分区域（头发顶部、脸部、衣服中段、领口 / 领巾）统计出现最多的 4 的倍数色，再补齐相邻档；**至少保证皮肤 6–7 档、头发 6–7 档**。文件放 `references/palettes/<角色>_4x.json`，例：`<角色>_4x.json`。

色板按第 4 节的方法从成品图统计，存 `<角色>_4x.json`；不需要另找模板。

## 6 描边：2px，不要 4px（4px 已被用户否掉）



* 生成图通常只有头发有深色轮廓，衬衫 / 皮肤边缘只有 AA 过渡。

* 补到 4px：1080p 下约 2.7 屏幕像素，像贴上去的黑框（实测被否）。

* 定稿：**2px**（`thin` 1px + 1 圈）≈ 1080p 下 1.4 屏幕像素。

* 判据：把 4× 按 1080p 实际尺寸缩到 0.686 再放大 5 倍看肩线，不能出现一整圈明显黑带。

## 7 验收（像素版口径）



1. `alpha_values == [0,255]`；背景 alpha 0。

2. **`body_width`（肩线宽）落在体型表 ×4 宽度区间；`figure` 高度仍落表**；宽发角色的总 bbox 宽度按“不碰左右边缘（每侧 ≥8%）+ ≤1.15×人物高”判，不按表里的宽度上限判；`center_x ≈ 576`；`bottom_gap == 0`。

3. 每个与透明相邻的不透明像素都是 `41,34,52`（`edge_bad == 0`）。

4. `distinct_colors` **28–30**（不是 18–24，也不是几万）。

5. 6× 预览：无 “色阶断层”“大块死黑”“紫边过粗”。

6. 1080p 与 4K 各看一眼：4K 1:1 最锐；1080p 不跳像素、无摩尔纹。

7. 与旧 1× 成品并排只作世界尺寸对照；不要求再产出 1×。

## 8 体型比例：与 1× 同一张表，×4



| 体型        | 1× 高度   | 1× 宽度   | 4× 高度   | 4× 宽度   |
| --------- | ------- | ------- | ------- | ------- |
| 特别矮小 / 幼态 | 125–145 | 85–105  | 500–580 | 340–420 |
| 纤细 / 矮小   | 145–160 | 100–120 | 580–640 | 400–480 |
| 普通        | 155–165 | 120–140 | 620–660 | 480–560 |
| 高挑        | 162–170 | 120–145 | 648–680 | 480–580 |
| 丰腴 / 宽肩   | 155–165 | 140–155 | 620–660 | 560–620 |



* 按 `--height` 与构图落，不要 squeeze 硬拉宽。

* 表里的“宽度”是**肩线 / 躯干宽**；宽发角色的肩线外飘散发丝不计入（见 §1.5⑤）。总 bbox 仍要满足：发丝不碰画布左右边缘（每侧 ≥8%）、总宽 ≤1.15×人物高。

* 短颈、紧凑躯干、不要大头娃娃 ——prompt 里继续写，与分辨率无关。

## 9 落位与渲染口径



* 命名：`<gender>Upper<Name>4x.png`（如 `maleUpperExample4x.png`、`femaleUpperExample4x.png`）。**只交付 4×**；旧 1× 若已存在可留作对照，但不再为新角色产出。

* 加载器：key 末尾 `2x`–`9x` → `PPU = 100 × N`，世界尺寸不变（2.88×2.11），`FullRect`，pivot 抄原版。

* 滤镜：**Bilinear、mipmap 关**（像素画被缩到 0.686× 时，mipmap 会把像素糊成插画）。

* 调试：F8 在 1x → 2x → 4x 循环；站定的客人要等下一趟。

## 10 坑



| 坑              | 现象                        | 正确做法                                            |
| -------------- | ------------------------- | ----------------------------------------------- |
| 4× 忘了写像素画约束    | 出来是插画，和游戏原版两个世界           | prompt 保留 “严格像素画 / 大色块 / 颜色少 / 硬边”，再加 “高清像素画” 句 |
| 4× 沿用 18–24 色  | 色阶断层、衣服死白、头发一团            | 按原图实测重配 28–30 色                                 |

| 描边补到 4px       | 像贴上去的黑框                   | 2px；判据见第 6 节                                    |
| 构图放任模型         | 头占六成、aspect 0.86，按体型换算必超宽 | 写死 “头 38–40%、留白 8%、下缘胸口”，实测能到 0.765             |

## 11 已停用的口径（不要照做）

- **插画版 4×**（不限色、软 alpha、无描边、Bilinear + mipmap）已停用；本包不包含该流程。
- **1× 生成 / A-B 双版 / 嘴部像素级返工**已停用；只交付 4× 单版。

## 12 实测教训（泛化）

- **一次生图，批次内挑版**：重生成几乎一定换脸；不合格只换候选或改裁切/参数。
- **头身比**：画布 36–45% / 人物 bbox 46–58% 都属正常；「38–40%」是构图指令，不是验收尺。
- **宽发角色**：宽度按肩线量，肩线外发丝不计；只查“不碰边 + 总宽 ≤1.15×高”。
- **描边**：2px 定稿；4px 会像贴上去的黑框（实测被否）。
- **像素 vs 插画**：本项目要像素风（硬边、28–30 色）；插画版只作历史参考。
